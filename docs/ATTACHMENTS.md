# 파일·이미지 첨부 후속 작업 설계

현재 구현 범위는 채팅 바 도구 선택과 웹 검색/URL 접근 강제 사용이다. 파일·이미지는 비활성 메뉴만 표시하며 업로드, 저장, 모델 입력 처리는 아직 구현하지 않는다.

## 현재 구조와 필요한 변경

- `AgentRequest.query`는 2,000자 문자열이고 `ConversationTurn.content`와 서명 continuation도 텍스트 전용이다. 파일을 query에 base64로 넣으면 2.1MB 요청 상한과 2MB continuation 상한에 영향을 주므로 별도 업로드가 필요하다.
- 기록은 공용 PostgreSQL의 세션 JSON으로 복원된다. 첨부 원본/미리보기를 브라우저 object URL이나 로컬 경로에만 보관하면 다른 브라우저 및 재접속 복원이 불가능하다.
- 기존 `image_search`는 Wikimedia Commons 검색이다. 사용자가 올린 이미지의 이해/분석과 별도 기능이다. 기존 `read_page`도 웹 HTML/텍스트용이므로 업로드 PDF를 그 도구로 우회해서 읽지 않는다.
- 웹 출처는 실제 조회한 페이지 URL에서 ID를 만든다. 업로드 파일에 가짜 웹 URL을 부여하거나 검증된 웹 출처처럼 표시하지 않는다.

## 제안하는 데이터 흐름

1. `+` 메뉴에서 파일/이미지를 고르면 입력창 위 첨부 칩에 파일명·크기·업로드 상태·삭제 버튼을 표시한다. 이미지에는 미리보기를 추가한다. 대화 주제에 따른 전용 입력 폼은 추가하지 않는다.
2. 같은 origin의 별도 `/api/attachments` 바이너리 업로드에서 서버가 실제 형식·크기·이미지 디코딩 가능 여부를 검사한다. 기존 JSON API의 본문 제한을 전역으로 늘리지 않고 해당 업로드 경로에만 별도 제한을 둔다. 실패/업로드 중에는 전송을 막고 명확한 상태를 표시한다.
3. 공용 PostgreSQL에 첨부 메타데이터와 작은 원본 바이너리(`bytea`)를 별도 테이블로 저장하는 초기 구성을 제안한다. 저장 구현은 분리해 향후 원본만 객체 저장소로 옮길 수 있게 한다. 디스크 전용 저장과 모델 제공자의 임시 file ID만으로 기록 복원을 구현하지 않는다.
4. `/api/agent`에는 `attachment_ids`만 전달하고, 서버가 실제 존재하는 첨부를 읽어 이번 턴 입력을 구성한다. 텍스트 파일은 한도 내 추출 텍스트, 이미지는 모델의 이미지 입력으로 전달한다. PDF는 페이지별 텍스트/이미지 입력 여부와 토큰 예산을 다음 작업에서 확정한다. 메뉴 선택 자체를 가짜 함수 도구로 만들 필요는 없다.
5. 응답 노드에는 첨부 ID·이름·형식·미리보기 경로를 저장한다. 서버가 제공하는 첨부 ID와 해당 메시지 연결을 검증하며, 후속 대화의 첨부 참조는 서명 continuation에도 포함할 수 있도록 버전을 갱신한다. 기존 텍스트 continuation과 기록은 계속 읽을 수 있어야 한다.
6. 기록 열기는 저장된 원본/미리보기/추출 결과만 복원한다. 모델 분석·OCR·파일 재업로드를 자동 재실행하지 않는다. 사용자가 새 질문을 보낼 때에만 필요한 첨부 입력을 모델에 전달한다.

## 구현 시 결정 및 검증 항목

- 처음에는 PNG/JPEG/WebP 이미지와 UTF-8 텍스트를 지원하고, PDF는 본문 추출/페이지 참조 설계와 함께 추가하는 순서를 제안한다. Office 파일/압축 파일/실행 파일은 초기 허용 형식에서 제외한다. 용량·파일 수·픽셀 수·추출 문자/페이지 상한은 backend `.env` 또는 서버 환경변수로 관리한다.
- 이미지 리사이즈와 미리보기 생성, 형식 검사·손상 파일·과도한 픽셀 수 차단을 서버에서 처리한다. PDF/파일의 원문 지시는 사용자 지시가 아닌 자료로 취급한다. 추출 실패를 샘플이나 추측으로 대체하지 않는다.
- 자료 단위 참조는 `attachment_<UUID>`와 페이지/텍스트 구간으로 표현하고 웹 `ToolSource`와 구분한다. 기존 답변 구조화는 공개 답변만 재정리하며 파일에서 새로운 사실을 보강하지 않는다.
- 전송 전 삭제한 첨부와 만료된 미연결 업로드는 정리한다. 전송 후에는 메시지 참조를 보존하며, 세션 삭제 시 다른 메시지 참조가 없는 원본만 삭제한다. 업로드 취소와 응답 취소의 수명을 구분한다.
- 현재 제품의 공용 기록 범위를 따른다. 로그인·브라우저별 분리를 이 기능에 임의로 추가하지 않는다. 키·원문·base64·모델 파일 ID를 로그에 남기지 않는다.
- 테스트는 실제 유료 호출 없이 업로드 형식/용량 검증, 잘못된 첨부 ID, 취소·삭제·재시도, 멀티모달 요청 구성, PostgreSQL 복원 시 모델 호출 0회, 이전 기록 호환을 확인한다. 데스크톱·모바일에서 첨부 칩/미리보기와 viewport 유지도 검증한다.

다음 작업은 이 설계를 기반으로 업로드 API·저장·입력창 첨부·모델 입력·기록 복원을 함께 구현해야 한다. 현재 선택 도구의 `requested_tool`에 file/image 값을 미리 허용하지 않는다.
